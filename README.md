# Arcvox

AI voice dictation for Traditional Chinese (Taiwan), English, and Japanese. Offline or self-hosted, with user-editable prompts.

## Layout

- `core/` Rust core crate `arcvox-core` (Apache-2.0)
- `apps/desktop/` Tauri 2 desktop client (macOS first, Apache-2.0)
- `apps/ios/` iOS client (planned)
- `server/` self-hosted engine server (planned, AGPL-3.0)

## Engines and models

Arcvox can run speech recognition and text rewriting on the machine with downloaded model files. Manage them in Settings > Engines and models. On macOS 26, Apple's built-in dictation and language model can be used with no download; the language model requires Apple Intelligence to be turned on. The Apple dictation language is installed from the Apple Dictation engine in Settings > Engines and models with the "Install language" button and is shared with the system.

Model files are stored in the models directory shown on the Engines and models page. Custom files can be imported: ggml `.bin` for speech recognition, GGUF for text. Each model's license is shown in the model list.

## Profiles, dictionary and speed test

The Profiles page edits one profile at a time; the menu at its top lists every profile with the applications it is used in, and has a search field when there are many. Profiles > "Add profile" creates a blank profile or one from a preset: standard, mail, chat or code. The standard preset is a clean copy of the factory settings; the others copy the engines of the default profile and pre-fill the application matchers and a prompt addition for that kind of application. All fields can be edited afterwards. "Reset to factory settings" puts a profile's conversions, switches, language, prompt addition and examples back to the factory values, keeping its name and the applications it is used in; the engines go back to the local pair when both are still configured. Several profiles can be renamed, made the default or deleted together from "Manage profiles" at the foot of the profile menu.

Each profile converts the Chinese script of the recognised text and, separately, of the rewritten text. By default Simplified characters become Taiwan Traditional and the wording stays as it was spoken. Either pass can be set to any conversion the OpenCC dictionaries offer (Simplified, Traditional, Taiwan, Hong Kong and Japanese forms, with or without phrasing), can convert quotation marks along with the characters, or can be turned off.

The Profiles page lists the nine stages a dictation passes through, from capture to the stored record, with each stage's current setting and what it did in the profile's newest dictation; selecting a stage shows the text it handed on, with the changes marked, beside its settings. A profile also chooses whether the dictionary's terms are given to the recognition engine and to the rewrite model, whether the front window's title is given to the model, and whether a rewrite much shorter than the spoken text is refused in favour of the recognised text.

A dictionary term can span several lines. When one of its aliases is spoken, the whole term is inserted as written. For terms of this kind, their aliases are sent as the speech hint in place of the text, and the term is left out of the term list given to the language model.

The Speed test page, opened from the link at the foot of the Engines and models page, records a sentence, or uses a kept history recording, and runs it through the selected engines with a cold run and a warm run each. It measures speed only. Results are not saved.

## Permissions and password fields

The macOS client needs the Accessibility permission to insert text and the Microphone permission to record. When the Accessibility permission is taken away while Arcvox runs, the shortcuts stop at once and the menu-bar menu names the problem; they work again as soon as the permission is given back. The Input Monitoring permission is not needed and does not stand in for Accessibility. Settings > General shows the state of both permissions and is the one place that opens the system's settings for them; the menu-bar menu, the settings window and the panel next to the widget lead there. Text that cannot be put into an application for lack of the permission is shown in the panel with a Copy button.

While macOS reports Secure Input (a password field has the keyboard), Arcvox does not insert text; a panel next to the widget shows the result with a Copy button. This depends on the application turning Secure Input on. Terminal does so for password prompts; in iTerm2 it is the "Secure Keyboard Entry" option; a terminal that never turns it on cannot be told apart from ordinary typing, so text dictated at its password prompt is inserted.

The recording shortcut is the fn key at first. Settings > Recording takes any number of shortcuts, recorded by pressing them: a modifier key alone (left and right are different keys), several modifiers, modifiers with one more key, or a mouse button other than the left and right ones. A combination or mouse button that is a shortcut is not passed on to the application in front. Letters, digits and symbols alone, combinations the system or most applications use, Esc and Caps Lock cannot be shortcuts. Every shortcut works the same way: hold to speak, press twice quickly for hands-free dictation. Other keys pressed while a shortcut is held reach the application and the recording goes on; Esc cancels a dictation.

The settings are on five pages: General (language, launch at login, permissions, the floating widget), Recording (shortcuts, microphone, recording length), Data and privacy (history, recordings, statistics, the context given to the rewrite), Backup and transfer (export and import of settings, content and records, backing up to a folder, the devices the records come from) and Advanced (timeouts, retries, how the text is put into applications). The Statistics page is a grid of cards; "Customize" lets each card be dragged to another place, resized within the sizes it supports, or hidden, and the arrangement is kept in the settings. The menu of the menu-bar icon names the app and its version, shows the state, copies the last result, and opens the history, the statistics and the settings; when the state is a problem, the item under it opens the place to resolve it. The menu also lists what else needs attention (a permission that is not allowed, a profile whose engine is gone or whose model is not downloaded, a model file that is gone, a backup folder that cannot be used), each with an item that opens the page where it is resolved, and the settings window marks those pages in its sidebar, which ends with the name and version of the app. The settings window opens only when asked to: a problem never opens it or changes its page. A floating widget that stays on screen while no dictation goes on can turn faint after a chosen time; it comes back when the pointer is over it or a dictation begins. Settings > General can preview the widget: it stays on screen where it can be dragged into place, shows the settings below as they are changed and before they are saved, and can be put into each state of a dictation or play one through with a sample text. A setting that differs from its default shows a reset button next to it, which names the default; each group of settings has a reset for the whole group. A reset changes the page only, and takes effect when saved.

The text can be put into an application in four ways, chosen under Settings > Advanced as a default and per application: pasted (the clipboard is used for the paste and then gets its earlier content back), typed as keyboard input, written through the Accessibility API (paste is used where the application does not take it), or copied to the clipboard only, with nothing put into the application. A separate switch leaves the text on the clipboard after every dictation, whichever way is used.

A dictation that fails is explained in a panel next to the widget, with its detail and a Copy button, until it is dismissed or the next dictation starts. Hands-free dictation can end by itself after a pause: Settings > Recording. The floating widget has three sizes in the same place. While it listens, outlines around its ring and bars behind its label follow the input level. The ring's colour tells how a dictation ended: green when the text was inserted or copied, amber when the text exists but needs attention (it was not inserted, or the rewrite did not succeed), red for a failure. A widget that rests shows the app's mark, a ring with a gap and a dot in the gap; the gap closes over the dot when a dictation begins and opens again afterwards. The widget and the panel follow the light or dark appearance of the system, and so does the icon in the Dock. While a dictation is processed, the panel shows the recognised text and then what the processing changed in it; this can be switched off there too.

Requests to an engine over the network are tried again after a connection failure, a server error or a timeout; the number of retries is set in Settings > Advanced. When recordings are kept, the recording is written while it is being made and completed as soon as the shortcut is released, before it is processed, so a failure at any later point, or the app ending at any moment, leaves what was said up to then in the history to be processed again; a dictation without speech or a cancelled one leaves nothing. With recordings switched off nothing is written, and a failed dictation cannot be processed again. Recordings are kept next to the history; Settings > Data and privacy can move them to another folder and opens that folder. When recordings are kept, a dictation that failed is listed in the history with its recording and can be processed again there. Any history row with a recording can be run again with the same or another profile, and the new result replaces the text only when accepted. The History page lists dictations by day, a hundred at a time as the list is scrolled, and can be narrowed by a search, to rows with a recording, or to a period: a quick choice such as today or the last seven days, or days picked in a calendar that shows how many rows each day holds, down to a span of hours within one day.

Settings > Backup and transfer moves three kinds of data between computers, each as a file of its own. Settings are how the app behaves on a device: shortcuts and recording, insertion method, general settings, appearance. Content is what the user made: profiles, engines, dictionary, base prompt. Records are what use produced: the history, the statistics and the recordings. A settings file and a content file are JSON files with the items that were ticked; importing one replaces the ticked items and keeps a copy of what was there. API keys are never written, and neither are the values of an engine's extra headers, the folder of a model file, the microphone, the display the widget is fixed to or window positions; an engine that needs a key asks for it again on the other computer. A records file (`.arcvox`) holds the history (each dictation with what its stages did), the statistics and, when ticked, the recordings. Importing records merges them into the ones that are there: nothing is replaced by something older, and importing the same records again changes nothing. Every installation has an identity of its own and a name that can be changed; the records of each device are kept apart, the Statistics and History pages show the total, and the records of another device can be removed again. None of these files is encrypted, and records with history hold the dictated text. Recordings take much more space than the other items.

With a folder chosen under "Back up to a folder", the app backs up this device's data there: its settings, its content and its records, as ticked. "Back up now" does it once; with "Back up automatically" on, it happens a few minutes after a change and once more when the app quits. Each time only what changed is written. The page shows when the folder was last backed up and what that wrote. The folder holds text files, one per month for the records, and the recordings, so it can be synced or copied elsewhere with other tools, and another computer can import the records from it. A folder that is no longer there (a volume that is not mounted, a folder that was removed) or that cannot be written is reported on the page and by the menu-bar icon, whose menu leads to the page; the page follows the folder while it is open. Such a folder is not written to. A missing folder can be made again from the page, and with "Create the folder again when it is missing" on, automatic backup makes it again at the same place and backs up this device's data to it in full. The app only adds to the folder and updates what is there: rows and recordings removed from the app later, by hand or by the retention settings, stay in the folder.
