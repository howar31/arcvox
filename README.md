# Arcvox

AI voice dictation for Traditional Chinese (Taiwan), English, and Japanese. Offline or self-hosted, with user-editable prompts.

## Layout

- `core/` Rust core crate `arcvox-core` (Apache-2.0)
- `apps/desktop/` Tauri 2 desktop client (macOS first, Apache-2.0)
- `apps/ios/` iOS client (planned)
- `server/` self-hosted engine server (planned, AGPL-3.0)

## Engines

Arcvox can run speech recognition and text rewriting on the machine with downloaded model files. Manage them in Settings > Engines: every downloaded or imported model is an engine of its own, named after the model, and goes away with the model file. On macOS 26, Apple's built-in dictation and language model appear as engines of their own with no download; the language model requires Apple Intelligence to be turned on. The Apple dictation language is installed from the Apple Dictation row with the "Install language" button and is shared with the system. Only engines for network services are added by hand: a name, the service's base URL, the model name and an API key; the engine transcribes or rewrites according to the tab it was added from. Each tab also sets the default engine of its kind: the one every profile uses unless it names an engine of its own, and the one a profile falls back on while the engine it names cannot run. A new installation starts with the recommended local pair as the defaults.

Model files are stored in the models folder shown on the Engines page; the folder can be changed there, and the files move with it. Custom files can be imported, or put into the folder's `custom` subfolder by hand, loose or in a folder of their own; each file's header tells what it is used for. A ggml `.bin` file is a speech recognition model. A GGUF file is a text model, unless its header marks it as a speech recognition model; such a model (for example Qwen3-ASR) hears through an audio encoder file (`mmproj`) that must be beside it, and a text model with an audio encoder beside it is listed for both speech recognition and text. A text model with a reasoning mode (such as Qwen3) is run with reasoning off, so only the rewritten text comes back. Each model's license is shown in the model list.

## Profiles, dictionary and speed test

The Profiles page edits one profile at a time; the menu at its top lists every profile with the applications it is used in, and has a search field when there are many. Profiles > "Add profile" copies one of the built-in templates: casual, formal, verbatim, polished or blank. A template is a whole profile, from the engines to the applications it applies to. The casual, formal and verbatim templates name the engines their writing style was tuned with, and a profile made from them can be switched to the default engines afterwards; the blank template follows the default engines. Casual is the everyday style and the profile a new installation starts with: it writes like a chat message, with no full stop after the last sentence and a question mark on questions; formal pre-fills the mail applications and writes complete sentences that end in a full stop, leaves spoken particles out, keeps greetings as dictated and breaks long text into paragraphs; verbatim keeps every word as spoken, retractions and fillers included, fixes misheard characters only and adds punctuation; polished keeps the meaning and rewords it for the reader, turning anger, blame, sarcasm and swearing into calm wording and orders into requests; blank leaves every option at its untuned default. All fields can be edited afterwards. Profiles are renamed, reset, made the default or deleted from "Manage profiles" at the foot of the profile menu, where several can be deleted together and each profile shows the template it was made from. A reset makes a profile a copy of its template again, engines and applications included; only the name stays. When that template is no longer in the app, the reset offers the casual one instead. When a new version of the app changes a template's writing style, a profile that still has the style its template shipped with takes the new one; a profile with a style of its own keeps it and says so on its rewrite stage, in the profile list and in the menu of the menu-bar icon, with a choice to take the new style or keep its own. The base prompt is brought to the shipped text in the same way while it was never edited; an edited one stays, and its page shows the difference.

A profile's engine for each stage is chosen from a list that opens under the current choice: "follow the default engine" first, then the engines in the groups of the Engines page, with the ones that cannot run last and marked with the reason, and a search field when there are many; the line under the choice says what the chosen engine is and whether it can run. The rewrite stage's list ends with "no rewrite". The engine a profile's template was tuned with is marked as suggested; other engines work too, with different results. When the engine a profile names is gone or cannot run, the profile keeps naming it, runs on the default engine meanwhile, says so on its page with a way to download the model, and uses the named engine again as soon as it can run. A model a template or a profile names that is not installed yet is listed as not downloaded until it is.

Each profile converts the Chinese script of the recognised text and, separately, of the rewritten text. By default Simplified characters become Taiwan Traditional and the wording stays as it was spoken. Either pass can be set to any conversion the OpenCC dictionaries offer (Simplified, Traditional, Taiwan, Hong Kong and Japanese forms, with or without phrasing), can convert quotation marks along with the characters, or can be turned off.

The Profiles page lists the nine stages a dictation passes through, from capture to the stored record, with each stage's current setting, what it did in the profile's newest dictation and, for the text stages, how long it took; selecting a stage shows the text it handed on, with the changes marked, beside its settings, and the page opens on the stage it was left at. The record of the recognition stage also keeps what a local speech model decoded beyond the text: its segments with their times, and each word with the model's confidence in it. A profile also chooses whether the dictionary's terms are given to the recognition engine and to the rewrite model, whether the front window's title is given to the model, and whether a rewrite much shorter than the spoken text is refused in favour of the recognised text. The last text stage applies fixed rules that need no judgement: the dictionary's aliases, and four switches the profile sets, each on or off: a full stop ending the whole text is dropped (on in the casual template, off in the formal and verbatim ones), a text ending in 嗎 or 呢 with no mark gets a question mark, a full stop right after 嗎 or 呢 inside the text becomes a question mark, a space goes between a CJK character and an ASCII letter or digit, and a half-width mark after a CJK character becomes full-width.

A dictionary term can span several lines. When one of its aliases is spoken, the whole term is inserted as written. For terms of this kind, their aliases are sent as the speech hint in place of the text, and the term is left out of the term list given to the language model.

The Dictionary page also suggests terms. When dictations the user corrected show the same text heard as something else, the kept text is offered as a term with the heard text as its alias, with the number of corrected dictations and a line from one of them; adding it puts it into the list, and an ignored suggestion is not shown again. A Chinese word corrected once is offered without its alias, as a recognition hint only, because an alias is replaced wherever it appears. Nothing is added to the dictionary by itself.

The Speed test page, opened from the link at the foot of the Engines page, records a sentence, or uses a kept history recording, and runs it through the selected engines with a cold run and a warm run each. It measures speed only. Results are not saved.

## Permissions and password fields

The macOS client needs the Accessibility permission to insert text and the Microphone permission to record. When the Accessibility permission is taken away while Arcvox runs, the shortcuts stop at once and the menu-bar menu names the problem; they work again as soon as the permission is given back. The Input Monitoring permission is not needed and does not stand in for Accessibility. Settings > General shows the state of both permissions and is the one place that opens the system's settings for them; the menu-bar menu, the settings window and the panel next to the widget lead there. Text that cannot be put into an application for lack of the permission is shown in the panel with a Copy button.

While macOS reports Secure Input (a password field has the keyboard), Arcvox does not insert text; a panel next to the widget shows the result with a Copy button. This depends on the application turning Secure Input on. Terminal does so for password prompts; in iTerm2 it is the "Secure Keyboard Entry" option; a terminal that never turns it on cannot be told apart from ordinary typing, so text dictated at its password prompt is inserted.

The recording shortcut is the fn key at first. Settings > Recording takes any number of shortcuts, recorded by pressing them: a modifier key alone (left and right are different keys), several modifiers, modifiers with one more key, or a mouse button other than the left and right ones. A combination or mouse button that is a shortcut is not passed on to the application in front. Letters, digits and symbols alone, combinations the system or most applications use, Esc and Caps Lock cannot be shortcuts. Every shortcut works the same way: hold to speak, press twice quickly for hands-free dictation. Other keys pressed while a shortcut is held reach the application and the recording goes on, also during hands-free dictation, which ends as soon as a shortcut is tapped. Esc cancels a dictation: nothing is put anywhere, and what it had produced by then, the recording when recordings are kept and the text of the stages that had run, stays in the history as a cancelled entry, to be copied or processed again from there; whether Esc also cancels a dictation already being processed is a setting. An Esc that cancels a dictation is not passed on to the application in front; at any other time Esc reaches it as usual.

The settings are on four pages: General (language, launch at login, permissions, the floating widget, the typing speed the statistics assume), Controls (shortcuts, microphone, recording length, how the text is put into applications), Privacy (how long entries, stage records and recordings are kept, the space they take, the context given to the rewrite) and Backup (export and import of settings, content and records, backing up to a folder, the devices the records come from); timeouts, retries, whether the local language model is loaded as soon as a recording starts, and its unloading after idle are set at the foot of the Engines page. The Statistics page is a grid of cards; "Customize" lets each card be dragged to another place, resized within the sizes it supports, or hidden, and the arrangement is kept in the settings. The menu-bar icon shows the state: the mark while nothing goes on, its gap closing over the dot when a dictation begins, a ring with a slowly breathing dot while it listens, a gap going round while the text is processed, a check mark, an exclamation mark or a cross for a moment when it ends, the gap opening again afterwards, and a badge while something needs attention; with reduced motion on in the system, it changes between still pictures. The menu of the menu-bar icon names the app and its version, shows the state, copies the last result, opens the history and the statistics, lists the profiles under the default one (ticked; picking another makes it the default), pauses dictation for a game or a presentation (ticked while it is paused: the shortcuts start nothing and every key reaches the application in front, the widget stays off the screen, the settings window shows a banner with a resume button, and the pause ends with the next start of the app), holds the widget's choices, and opens the About page and the settings window as it was last left; when the state is a problem, the item under it opens the place to resolve it. The menu also lists what else needs attention (a permission that is not allowed, a profile running on the default engine because the one it names cannot run, a profile with a writing style of its own whose template has a new one, a default engine that cannot run, a model file that is gone, a backup folder that cannot be used), each with an item that opens the page where it is resolved, and the settings window marks those pages in its sidebar, which ends with the name and version of the app. The settings window opens only when asked to: a problem never opens it or changes its page. A floating widget that stays on screen while no dictation goes on can turn faint after a chosen time; it comes back when the pointer is over it or a dictation begins. Settings > General can preview the widget: it stays on screen where it can be dragged into place, shows the settings below as they are changed and before they are saved, and can be put into each state of a dictation or play one through with a sample text. A setting that differs from its default shows a reset button next to it, which names the default; each group of settings has a reset for the whole group. A reset changes the page only, and takes effect when saved.

The text can be put into an application in four ways, chosen under Settings > Controls as a default and per application: pasted (the clipboard is used for the paste and then gets its earlier content back), typed as keyboard input, written through the Accessibility API (paste is used where the application does not take it), or copied to the clipboard only, with nothing put into the application. A separate switch leaves the text on the clipboard after every dictation, whichever way is used.

A dictation that fails is explained in a panel next to the widget, with its detail and a Copy button, until it is dismissed or the next dictation starts. Hands-free dictation can end by itself after a pause: Settings > Recording. The floating widget has three sizes in the same place. While it listens, outlines around its ring and bars behind its label follow the input level. The ring's colour tells how a dictation ended: green when the text was inserted or copied, amber when the text exists but needs attention (it was not inserted, or the rewrite did not succeed), red for a failure. A widget that rests shows the app's mark, a ring with a gap and a dot in the gap; the gap closes over the dot when a dictation begins and opens again afterwards. The widget and the panel follow the light or dark appearance of the system, and so does the icon in the Dock. While a dictation is processed, the panel shows the recognised text and then what the processing changed in it; this can be switched off there too.

Requests to an engine over the network are tried again after a connection failure, a server error or a timeout; the number of retries is set at the foot of the Engines page. When recordings are kept, the recording is written while it is being made and completed as soon as the shortcut is released, before it is processed, so a failure at any later point, or the app ending at any moment, leaves what was said up to then in the history to be processed again; a dictation without speech leaves nothing. A failed or cancelled dictation is listed in the history whether or not recordings are kept; without a recording it cannot be processed again. Recordings are kept next to the history; Settings > Privacy can move them to another folder and opens that folder. Any history row with a recording can be run again with the same or another profile, and the new result replaces the text only when accepted. An expanded row shows the recognised text, the recording and the controls to process it again; what each stage changed and the results the row has had are two blocks that open on request and stay as they were left. The results are listed one per line with the one in use first and shown whole; the others open when pressed, with the text, a copy button and the button that puts the result in use; beyond five, the rest are shown on request. The History page lists dictations by day, a hundred at a time as the list is scrolled, and can be narrowed by a search, to rows with a recording, or to a period: a quick choice such as today or the last seven days, or days picked in a calendar that shows how many rows each day holds, down to a span of hours within one day. The line above the list counts the rows and recordings shown and clears them: all of them, or only the chosen period's, with or without their text.

Settings > Backup moves three kinds of data between computers, each as a file of its own. Settings are how the app behaves on a device: shortcuts and recording, insertion method, general settings, appearance. Content is what the user made: profiles, engines with the default pair, dictionary, base prompt (its page can restore the shipped text, showing the lines that would change first). Records are what use produced: the history, the statistics and the recordings. A settings file and a content file are JSON files with the items that were ticked; importing one replaces the ticked items and keeps a copy of what was there. API keys are never written, and neither are the values of an engine's extra headers, the folder of a model file, the microphone, the display the widget is fixed to or window positions; an engine that needs a key asks for it again on the other computer. A profile that names an engine the other computer does not have keeps naming it and runs on the default engine there; a default engine the file names that is not there is set back to the shipped one. Profiles and a base prompt written by an older version are brought to the current shipped texts the way an update does it. A records file (`.arcvox`) holds the history (each dictation with what its stages did), the statistics and, when ticked, the recordings. Importing records merges them into the ones that are there: nothing is replaced by something older, and importing the same records again changes nothing. Every installation has an identity of its own and a name that can be changed; the records of each device are kept apart, the Statistics and History pages show the total, and the records of another device can be removed again. None of these files is encrypted, and records with history hold the dictated text. Recordings take much more space than the other items.

With a folder chosen under "Back up to a folder", the app backs up this device's data there: its settings, its content and its records, as ticked. "Back up now" does it once; with "Back up automatically" on, it happens a few minutes after a change and once more when the app quits. Each time only what changed is written. The page shows when the folder was last backed up and what that wrote. The folder holds text files, one per month for the records, and the recordings, so it can be synced or copied elsewhere with other tools, and another computer can import the records from it. A folder that is no longer there (a volume that is not mounted, a folder that was removed) or that cannot be written is reported on the page and by the menu-bar icon, whose menu leads to the page; the page follows the folder while it is open. Such a folder is not written to. A missing folder can be made again from the page, and with "Create the folder again when it is missing" on, automatic backup makes it again at the same place and backs up this device's data to it in full. The app only adds to the folder and updates what is there: rows and recordings removed from the app later, by hand or by the retention settings, stay in the folder.
